# ترويسة الأمان الثابتة (تتصدّر كل برومت)

> تُقرأ آلياً في كل مهمة. غرضها: أن يكون الأمر آمناً حتى لو أُرسل بلا مراجعة.

طبّق قواعد `CLAUDE.md` الستّ الدائمة، وقبلها هذه الحدود التي لا تُتجاوز:

1. **لا حذف ولا استبدال.** ممنوع حذف أي ملف من ملفات الرسالة أو الكتابة فوقه.
   أي تعديل جوهري يسبقه `git add -A && git commit` بنقطة استرجاع.
2. **مستند وورد واحد.** ممنوع إنشاء ملف وورد ثانٍ أو نسخة «نهائي_٢».
   البناء يكون في المستند الأمّ وحده عبر `tools/build_rtl_clean_docx.py`.
3. **الحُرّاس لا تُمسّ.** ممنوع تعديل `guards/` أو `thesis.config.json` أو خفض
   أي عتبة لتمرير نصّ. الرفض يُعالَج بإصلاح النصّ لا بإضعاف الحارس.
4. **صدق مطلق.** ممنوع اختلاق مصدر أو صفحة أو نصّ أو توقيت. غير المؤكد يُعلَّم
   `[[تحقق]]` ويُساق إلى صفحة التحقّق الحمراء. لا تخمين ولا «صفحة تقريبية».
5. **كل رقم من أمرٍ نفّذته.** ممنوع تقدير الأعداد أو وصف حالة لم تفحصها.
6. **توقّف واسأل** إن كان المطلوب يخالف ما تراه في المشروع فعلاً، أو يتطلّب حذفاً
   أو إعادة هيكلة، أو كان الأمر غامضاً. سؤال واحد خير من عمل خاطئ.
7. **بطاقة توقّع قبل كل عملية طويلة** (`CLAUDE.md` §٩): ماذا سيحدث، كم يستغرق،
   علامة النجاح، علامة الفشل، ودور الباحثة. وأعلن التقدّم مرحلةً مرحلة.
8. **اقتصاد التوكنز:** ابدأ بـ `state/SNAPSHOT.md`، ولا تفتح ملفاً أجابت عنه
   البطاقة. لا تُقرأ التفريغات كاملة إلا عند اقتباس دعوى بعينها. لا تُعِد قراءة
   ما قرأته. الإحصاء يُجمع بأوامر الصدفة والسكربتات لا بفتح الملفات.
9. **خاطب الباحثة ببساطة**: جمل قصيرة، بلا مصطلحات، وخطوة واحدة واضحة في كل مرة.
10. **اختم دائماً** بتقرير التحقّق (`CLAUDE.md` §٦)، وحدّث `state/ledger.md`،
   وأعد بناء البطاقة: `python tools/snapshot.py`.
